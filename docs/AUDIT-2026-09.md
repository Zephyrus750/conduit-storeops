# Conduit audit: feature parity, UI, security (2026-09-23)

A read-only audit of Conduit against the four programs it replaces:
- ShelfSearcher (`SHELFSEARCHER-CK-V2`)
- Decant Visualiser (`decantvisualiserv1`)
- K2B (`k2b-coolwisp`, including its worker `cloudflare-worker.js`)
- Vector (`vector-suite`, including the "Conduit Shell Swap" showcase)

It also covers a browser pass of the shell at 1920×1080, 1440×900, 960×1040 and 420×860, and a security review of the worker, the shared modules, the client and the shell.

`npm test` passes: 79 of 79. Paths are relative to this repo unless they are prefixed:
- `K2B:` for k2b-coolwisp
- `DV:` for `decantvisualiserv1/decant`
- `SS:` for `SHELFSEARCHER-CK-V2/shelfsearcher`
- `V:` for vector-suite

Priorities:
- **P0**: wrong data, a security hole, or it blocks retiring a legacy app.
- **P1**: a floor, paper or desk workflow the stores use every day.
- **P2**: parity and polish.

---

## 1. Summary

**Conduit's core is sound.** It has:
- one event log per store;
- pure shared reducers;
- actor taken from the token;
- an offline outbox;
- a release-cached shell;
- no horizontal overflow and no console errors at any size.

Every legacy module has a first port. The gaps fall into six groups:

1. **Correctness bugs in ported views.** Backfill accuracy, the Adjust SOH sign, dates computed in UTC, the dock "Add & flag" action, and finalising with running pallets. They produce wrong numbers today (§2).
2. **Security.** There are four P0 holes:
   - the sign-in lockout can be bypassed;
   - event entity keys can pollute object prototypes;
   - a manifest can be deleted without the dock role;
   - no session can be revoked.

   Several P1 hardening items follow (§3).
3. **Hidden legacy dependencies.** The product catalogue still comes from the K2B worker and the `k2b-details` worker. Maps can only be made in ShelfSearcher's editor. The shell's CSS source is a showcase on a vector-suite branch that is not `main` (§4).
4. **Camera, barcodes and paper.** No part of Conduit uses a camera, renders a barcode, or prints a real sheet. That covers K2B's Keycode›Barcode loop, refresh and stocktake scan-walks, decant consol scanning, and every print flow. Vector's CLAUDE.md calls the floor, phone and paper interface "sacred" (§5.1).
5. **Missing modules.** Decant's facilitator, Team Board, wallboard and analytics. K2B's end-of-day rollover, screen scan, stockroom intelligence and trends. ShelfSearcher's print composer, inventory hub, evacuation route, suggest-edits and map editor (§5).
6. **UI.** Two blocking phone and navigation bugs, then a list of layout, dark-mode and accessibility issues (§6).

## 3. Security findings

These are ordered by severity. Each fix stays inside the non-negotiables: events stay the one write path, and the actor comes from the token.

### High

**Status (2026-09-23): High 1–4 fixed**, with contract tests. Notes:
- #1: failures now count per device (5, cleared on success), per store (30 an hour) and per network address (200 an hour; stores can share one address). A success clears only the device counter. Device ids are restricted to plain characters. Owner sign-in has a device, an owner-wide and a network key. Unlock is per device plus store and network. The 6-digit PIN minimum is still to do.
- #2: `shared/validate.js` refuses prototype names as entity keys or values, as payload keys, and as strings anywhere in a payload. Entity values must be strings or numbers of 100 characters or fewer.
- #3: the role is checked first, and the document is deleted only after `manifest.remove` is accepted.
- #4: each store has a credential epoch in its tokens. A new PIN or code, `status: suspended` or `revoke: true` moves the epoch on, deletes the store's refresh tokens, and the store object refuses older tokens and closes their sockets. `POST /v1/auth/signout` deletes the refresh token, and the client calls it on sign-out. Owner refresh tokens stop working when `OWNER_KEY_HASH` changes. The owner console has "Sign out every device" and a `suspended` status. Owner access tokens still last until they expire (12 h).

**Status (2026-09-23): Medium 5–12 fixed.** Notes:
- #5: `netlify.toml` sends a CSP (scripts from this origin only; `connect-src` is the worker allow-list, kept in step with `js/config.js` by a unit test), `X-Frame-Options: DENY` and a `Permissions-Policy`. SheetJS is self-hosted under `vendor/xlsx/` (0.18.5 from npm, Apache-2.0), which also fixes offline manifest upload (§4).
- #6: `shared/svgsafe.js` allow-lists map markup at publish and reports how much was stripped. The Busselton map passes through byte for byte. Maps published before this change should be published again.
- #7: `?worker=` and the remembered worker are honoured only for origins on `WORKER_ALLOWED` (or localhost when the shell runs locally). The sign-in names any worker that is not the default.
- #8: `csvCell` neutralises formula-looking text in the worker exports and in every client copy-as-CSV.
- #10: the socket sends its token as a subprotocol. `?token=` is accepted on `/ws` only, for older installed shells.
- #11: unlocked roles last `ROLE_TTL_SECONDS` (12 h), then refresh drops back to the Floor. The access token ends with the role.
- #12: done with High #1 (per device, plus store and network).
- #9: decided and fixed. Stockroom and Back dock reads need that area's code or the manager code, on every read path (snapshot, changes, socket, history, export, life, manifests, profiles). The owner still reads every area. The Floor dashboard shows a locked card that opens the code sheet. After unlocking, the device fetches a full snapshot, and a device that loses a role drops that area's data. Sign-out also clears the cached snapshot.


1. **The sign-in lockout can be bypassed.** Store sign-in locks on `signin:<store>:<device>` and owner sign-in on `owner:<device>`. `device` is a string the client sends (`worker/index.js:23,26`, `worker/registry.js:98`), so a new device string gets a fresh set of attempts. Store PINs are 4–8 digits, so the lockout is the only real barrier.
   - Fix: count failures per store (and per owner) in addition to per device, using a sliding window. Add a Cloudflare rate limit on `/v1/auth/*` keyed by client IP (the `CF-Connecting-IP` header). Consider requiring PINs of at least 6 digits.
2. **Event entity keys can pollute object prototypes.** Reducers index plain objects with keys taken straight from `entity` or `payload`. Examples: `s.refresh.weeks[e.entity.week] ||= {}` and `s.labels.checks[e.entity.cycle] ||= {}` (`shared/reducers/floor.js:40-92`), the same pattern in the dock, plan and backfill projections, and the date-keyed maps. A key of `__proto__` or `constructor` resolves to the shared prototype. Any signed-in device can then corrupt state in the store object, and on every device that replays the log. Because the event is stored, the corruption returns after every restart.
   - Fix: in `shared/validate.js`, reject any entity or payload key and value that is used as a map key unless it matches a strict pattern: week ids, dates, bay codes, ULIDs, `/^[\w.-]{1,40}$/`, and never `__proto__`, `prototype` or `constructor`. Also create projection maps with `Object.create(null)` or use `Map`. Add a unit test per reducer.
3. **A manifest can be deleted without the dock role.** `DELETE /v1/store/:no/manifest/:manNo` checks only the store's back-dock entitlement. `removeManifest` runs the SQL `DELETE` *before* submitting the `manifest.remove` event (`worker/store.js:79,227-233`). When the event is then refused because the caller lacks the dock role, the document is already gone and nothing records its removal. That also breaks the "nothing silent" rule.
   - Fix: check the role first, submit the event, and delete the row only when the event is accepted. Better still, keep the row and treat the event as the tombstone, which fits rule 5.
4. **No session can be revoked.** Rotating the PIN or a code, removing an entitlement, or retiring a store does not invalidate existing refresh tokens. They keep their roles, including manager, and keep rotating for 30 days (`registry.js:137-152`). Access tokens stay valid for 12 hours. There is no server-side sign-out: `client/session.js:87` only forgets the token locally. A lost phone, or a leaked manager code, stays trusted until expiry.
   - Fix: store a per-store `credential_epoch` in the registry. Bump it on PIN or code rotation and on status change, put it in the claims, and check it on refresh and in `storeCall`. Delete the store's refresh rows when it is bumped. Add `POST /v1/auth/signout`, which deletes the refresh row. Add a `suspended` store status that refuses sign-in and refresh.

### Medium
5. **No Content-Security-Policy or frame protection on the shell** (`netlify.toml`). Rendering is `innerHTML` everywhere, so a single missed `esc()` becomes script execution.
   - Fix: add a CSP. Suggested: `default-src 'self'; connect-src 'self' <worker origins> wss://<worker>; img-src 'self' data: <catalogue image host>; style-src 'self' 'unsafe-inline' fonts; script-src 'self'; frame-ancestors 'none'`, plus `Permissions-Policy`. Self-hosting SheetJS (§4) removes the cdnjs exception.
6. **Map SVG sanitising is a regex deny-list.** `publishMap` rejects `<script` and `on…=`, and nothing else (`worker/store.js:291`). The SVG is then inserted with `innerHTML` on every device (`js/map.js:163`). Deny-lists miss other active content in SVG: `foreignObject`, `javascript:` links, animation of `href`, and separators other than whitespace. Only the owner can publish, but a compromised owner key would reach every store's devices.
   - Fix: sanitise with an allow-list in `shared/maprender.js` or the worker. Keep only the elements and attributes the map renderer emits, and strip `href` values that are not `#fragment`. Add the CSP above as a second layer.
7. **`?worker=` permanently repoints a device** (`js/shell.js:24-25`). Anyone can send a link that makes a store device send its PIN and codes to a look-alike worker, and the device keeps that setting.
   - Fix: allow only a fixed list of worker origins, or honour `?worker=` on localhost only. Always show the worker host on the sign-in screen when it is not the default.
8. **Spreadsheet formula injection in CSV exports.** `toCsv` does not neutralise cells that start with `=`, `+`, `-`, `@`, tab or CR (`shared/records.js:55-59`). The clipboard CSVs (`adjust.js`, `srhistory.js`) have the same gap. DV had this guard.
   - Fix: prefix those cells with `'`.
9. **Area data is readable with the store PIN alone.** Snapshots, `/changes`, history, export, life, manifests and profiles are gated by the store's *entitlement* (caps), not the device's *role*. A floor-only device (PIN, no code) therefore receives the full stockroom and back-dock projections and can export them.
   - Decide whether this is intended. If not, gate reads by role as well as entitlement.
10. **Tokens in URLs.** `requireClaims` accepts `?token=` on every route (`worker/index.js:175`), and the WebSocket URL carries it; the UI audit saw it in console error URLs.
    - Fix: accept `?token=` only on `/ws`, or use a short one-time WebSocket ticket.
11. **Unlocked roles never expire on a shared device.** A manager code typed once on a shared PDT stays for 30 days of refreshes. Legacy DV auto-locked idle manager screens after 5–60 minutes.
    - Fix: give area and manager roles a shorter lifetime than the store session, and let the owner set an idle re-lock.
12. **The unlock lockout is per store.** One device guessing codes locks every device in the store out of unlock for 15 minutes (`registry.js:101`).
    - Fix: combine this with #1, keyed per store and per IP.

### Low

**Status (2026-09-24): Low 13–18 fixed, plus the 6-digit PIN minimum.** Notes:
- #13: heartbeat fields are capped. The devices projection is documented in `worker/store.js` as the one deliberate write outside the log (telemetry, not history).
- #14: an events body or socket frame is capped at 8 MB and one event's payload at 2 MB. Entity values were already capped at 100 characters.
- #15: a device's `at` must be within 10 minutes ahead and 30 days behind the worker's clock (`clock_skew`). Owner imports are exempt.
- #16: store names and regions are trimmed, stripped of control characters and capped at 80.
- #17: the DV import address must be a public https site outside dev.
- #18: done with the read-gating change (sign-out clears the cached snapshot).
- New and rotated PINs must be 6–8 digits (`PIN_MIN_DIGITS`; dev and tests use 4). Existing PINs keep working until rotated.
13. **The heartbeat bypasses the write path.** `hb` writes into `state.devices` directly, outside the event log, which departs from rule 1. The `app` and `area` fields have no length limit and end up in snapshots (`worker/store.js:318-322`).
    - Fix: cap the strings. Either keep devices out of `state`, or record them as a documented exception.
14. **Event validation has no size limits.** There is no per-event payload size cap, no string length cap on entity values, and no cap on a request body before `request.json()`. Batches are capped at 500 events.
    - Fix: cap the body at about 1 MB and entity strings at about 64 characters.
15. **Device clocks decide conflicts.** `at` comes from the device and decides "first at wins" (refresh marks, and more). A device with a wrong clock wins or loses conflicts.
    - Fix: record `received`, which already exists, and bound `at` to within ±24 h of it.
16. **Store names and regions have no length or character limits** (`registry.js` `register` and `patch`). Rendering escapes them, so this is hygiene only.
17. **DV import fetches an owner-supplied URL** (`worker/import-dv.js`). Owner-only, but restrict it to the legacy DV origin.
18. **Clearing and upgrading.** Sign-out does not clear the IndexedDB snapshot or outbox for the store. On a shared device the next person can read cached area data offline before signing in.
    - Fix: clear per-store caches on sign-out, after flushing the outbox.

### Good as built
- PBKDF2-SHA256 with 100k iterations and salts.
- HMAC tokens with constant-time compare and an expiry check.
- Actor always comes from the claims.
- Validate runs before mutate, so a rejected event changes nothing.
- The store number in the event must match the token.
- Act-as tokens last 1 hour and cannot reach admin routes.
- Secrets are only in GitHub Actions and are piped through stdin.
- The owner key is stored as a hash only.
- The API is never cached by the service worker.
- `esc()` covers `& < > " '`.

## 5. What Conduit still needs, by area

### 5.1 Cross-cutting (P0/P1)
- **Camera scanning.** Use `BarcodeDetector` with a self-hosted ZXing fallback, with continuous mode, torch, zoom, duplicate guard, colour flash, beep and vibrate settings, and releasing the camera when hidden. It is used by refresh marking, the stocktake walk, label integrity, decant consols, cages, the backfill bay scan, and a scan-to-lookup sheet. The deferral is at `js/ui.js:25`.
- **K2B's Keycode › Barcode loop.** The camera OCRs keycodes off the PDT screen (Tesseract, 2–3 sightings, twin and near-miss guards), then renders each code as CODE128 or EAN-13 so it can be scanned back into the PDT. This is the floor workflow K2B's two live stores run on. Also enforce 7–8 digit keycodes and 13-digit APNs with a checksum (`shared/backfill.js:10-14` currently accepts any 6–13 digits).
- **Self-hosted barcode renderer** (Code128 and EAN-13). The desk focus view, bay header barcodes, SOH print lists and triage sheets all need it.
- **Print and paper, with real print layouts rather than `window.print()` of the page:**
  - backfill review worksheet (to add / to remove, tick boxes);
  - SOH adjustment list, combined and by department (Home, Kids, Clothing; Bulk on both), with barcodes;
  - day-list triage walk sheet with the SOH evidence page (`daylist.js:35` currently prints the page);
  - label-integrity marking sheets (all, per sub-department, per micro-department);
  - stocktake report with the missing list and CSV;
  - print composer (map, scope, layers, legend) and the department booklet;
  - DV printable receiving audit with the "Checked by / Date / Signature" line;
  - evacuation map, cage tags, maintenance work orders.
- **Departments registry.** An owner-editable taxonomy including Bulk; stockroom bay ranges → department (narrowest range wins); badges on review, history, phone and print. Use one naming source: the map chips and Label integrity currently disagree (§6). `shared/maprender.js:310 deptResolver` is a starting point.
- **Store settings document**, as events: timezone, dock grid size, standard minutes per carton, idle auto-lock, refresh focus schedule, screen-scan presets.
- **Omnisearch parity.** Bay, manifest, consolidation, cage, GS1, keycode-in-bay, product-name and alias search. A "whole life" product view. Voice search, or remove the dead mic icons.

### 5.3 Back dock (Decant Visualiser)

**P1**
- **Handover and timing.** A receiving confirmation hand-off (`receiving.confirm` / reopen). A **decant start time kept separate from landed**, and used for clear time, rate and goal.
- **Carry-over and rollover.** Leftovers kept or cleared at finalise, carried into the next truck, and `carriedOut` recorded. Decide whether to keep "one open truck at a time" or drop it on purpose.
- **Pallet work actions.** Join, hand over, leave, unstart; **fix times**; quarantine for a suspiciously quick "done"; an undo toast.
- **Hold-up kinds.** Huddle (ad hoc and a booked opening huddle), transition, team break, and a note on each. Report them separately from downtime, and have the importer keep the real kinds (they currently import as "Other"). Restore the "Cages out" label.
- **People on the truck.** Personal breaks and cutter / runner / cleaner roles. Worked time must exclude halts and breaks, and credit must be pro-rata instead of an even split.
- **Pallets.** Move a pallet to another square. Show a live timer and expected minutes, with over/under colours on the grid.
- **Shared screens.** A dock tablet with the big grid, one-second timers, a clock, wake-lock and fullscreen. A **Team Board** showing goal, forecast, progress with a goal-pace marker, who is decanting now, who is next, and D-numbers only.
- **Printable receiving audit** for a live or closed truck.

**P2**
- **Forecasting.** A schedule-based estimated clear time on every screen. Per-person queues with auto-balance, tubs first and a finish guard. Personal 28-day and 7-day rates and a plan basis. A default goal from recent clear times.
