## 1. Fix first: data safety

These can lose or corrupt store data, or stop a store working. None of them
needs a decision except 1.1's retention period.

| # | Finding | Where | Severity |
|---|---|---|---|
| 1.1 | **The store state is one SQLite row with no pruning (checked).** Cloudflare caps a Durable Object row at 2 MB. These grow without limit: closed trucks with their manifests (up to 250 lines a consolidation), backfill bays, adjustments, label variances, refresh weeks, planner days. The inventory hub can reach the cap on its own (24 loads × 3,000 lines). Once the snapshot insert fails, every batch is refused and the outbox stalls. The whole state also goes to every device. | `worker/store.js:103`, `shared/reducers/backdock.js` (nothing deletes trucks), `shared/reducers/stockroom.js`, `shared/reducers/floor.js` inventory caps | High |
| 1.2 | **Sending over HTTP skips other devices' changes (checked).** An accepted event is folded in with the worker's `seq`, which moves the device's `base.seq` past events from other devices it has not seen. `/changes?since=` and the socket `hello` then never return them, and the wrong state is saved. This affects every device on the polling fallback, and any send while the socket is down. | `client/store.js:131`, `:61` | High |
| 1.3 | **Rejected events can still change state (checked for `issue.update`).** `apply()` has no rollback, and these reducers change state before refusing: `issue.update` (a key, then a bad `sev` or `cat`), `pallet.update`, `plan.set` and `manifest.linkLate`. The worker keeps the change without logging it, and the next snapshot saves it. | `shared/reducers/floor.js:183-188`, `backdock.js:304`, `:504-516`, `:266-270` | High |
| 1.4 | **Devices can send event types only the worker should create (checked).** `map.publish`, `soh.publish`, `soh.remove`, `manifest.publish` and `manifest.remove` are accepted from devices. A manager can point the store at a map version that does not exist. Future-dated SOH publishes push real snapshots out, and their documents get deleted. | `worker/store.js` `applyOne` has no worker-only list | Medium-High |
| 1.5 | **Backfill accuracy without a report (checked).** A bay readied with no pasted report, auto-closed at the rollover, imported or unfinalised scores 100% if it has scans and 0% if it is empty. Those scores feed History, Trends, the dashboard and the console. K2B left these bays unscored and out of the averages. | `shared/reducers/stockroom.js:336-338`, `shared/kpis.js:19`, `shared/trends.js:23` | High |
| 1.6 | **Late phone scans don't reopen a bay (checked).** K2B put a Ready or Submitted bay back to pending when new codes arrived. Conduit's `submission.update` never changes status, so the bay keeps stale metrics. The desk can also ready a half-scanned bay, because "Send to review" sends nothing. | `shared/reducers/stockroom.js:155-176`, `js/views/stockroom/bfreview.js:287,419` | High |
| 1.7 | **Unescaped manifest numbers in the decant board (checked).** `${t.manifest.manNo}` and `${sl.manifest.manNo}` go into innerHTML. A slot manifest with no `consols` throws and breaks the board for every dock device. | `js/views/backdock/plan.js:111-112`, `manifests.js:33`; sources `backdock.js:243,509` | Medium |
| 1.8 | **Starting a running pallet does nothing, silently (checked).** The device still shows "D5 on A3" with Undo, and Undo then pops the segment of whoever really is on it. DV refused with "already running". This also breaks "nothing silent". | `shared/reducers/backdock.js:328`, `receiving.js:222,243` | Medium |
| 1.9 | **A server error on token refresh signs the device out.** Any non-network error clears the session, so a 500 or 429 from the registry does too. Two tabs refreshing at once can sign each other out. | `client/session.js:84`, `worker/registry.js:183` | Medium |
| 1.10 | **Two other client races (possible).** A poll that returns after a snapshot re-applies events, so `cage.scan` and `label.variance` count twice. Two quick `connect()` calls can open two sockets. | `client/store.js:150-161`, `foldIntoBase` | Medium |

## 2. Floor and shell

- **Confirmations:**

## 5. Code health, the rest

- **Sockets after role expiry:** they keep receiving stockroom and back-dock events after the role lapses; `broadcast()` doesn't check `exp`. Medium.
- **Photo delete is silent:** any store device can delete any issue photo, with no event logged, and the issue still lists it. Medium.
- **Payloads without size caps:**
  - `issue.log` and `issue.update` titles and notes;
  - `label.variance` and `label.assign` lists;
  - `submission.update` codes and `daylist.set`;
  - `cage.scan` keycode format and quantity;
  - `manifest.attach` consolidations;
  - `soh.verify` location.
  - These feed 1.1. Medium.
- **Time zones:**
  - `at` is compared as a string while devices write their own zone offset.
  - `addMonths` uses the UTC date, so a service logged before 08:00 in Perth gets a due date a day early.
  - Medium (possible).
- **Phone cost per event:** `rebuild()` deep-copies the whole state and stringifies every projection twice per event, then writes the whole state to IndexedDB. With a multi-MB state this is slow on a TC52x. Medium.
- **`GET /v1/catalogue`** is public with no rate limit and can trigger upstream detail fetches. Low-Medium.
- **Low items:**
  - A published `fill` can break out of `markerGlyph`'s markup.
  - The SVG sanitiser's `url(` check can be bypassed with a CSS escape.
  - The infinite `rf-done-pulse` animation runs on every refreshed shelf (map performance rule).
  - `dv-profiles/1` names a product (rule 7).
  - `store.tools.set` logs a change that changes nothing.
  - Manifest and map bodies are parsed before their size is checked.
  - Anyone can lock the owner out with 30 wrong keys an hour.

**Tests to add:**
- A generic "a rejected event leaves state unchanged" test, run against every reducer.
- Client tests: the HTTP-send seq jump, double apply after a snapshot, refresh on a 5xx.
- Worker-only types refused from devices.
- Photo delete permissions and the sweep.
- A state-size guard.
- Escaping in the decant board.
- Broadcasts stopping after a role expires.

**Good as built:**
- Read gating (`readable` and `needArea`) is consistent across snapshot, changes, socket, history, exports, manifests and profiles.
- Worker-side writes log their event before touching SQL.
- Actor and clock-skew checks hold.
- Remote values are escaped almost everywhere.

## 6. Suggestions beyond legacy

**Floor**
- A "stale shelves" layer in Refresh, coloured by weeks since last refreshed, to steer the weekly 100.
- Pick by product: scan a keycode, find its bays (catalogue and stock history) and add them to the route.
- A monthly emergency-equipment walk: scan each sign to log it, and print an evacuation map for the staff room.
- Maintenance work orders: a printed sheet with a QR code that opens the issue, and a "contractor visited" log entry.
- A status for wrong labels (logged, then fixed) with a printable fix list, so variances close out.
- Stocktake zones per device or D-number, with live progress and a finish estimate.

**Stockroom**
- A "sent" event from the phone, so a Ready bay with new scans returns to review with an "N new since ready" badge.
- Claim time limits with "take over".
- Map item barcodes to keycodes on the backfill phone (`apnPairs`, as Cages does).
- Share the pasted SIM report across the store, like SOH snapshots.

**Back dock**
- Server-stamped dock events, or a clock offset from each device's heartbeat with a warning above 60 s.
- Undo that targets the person.
- Team Board nudges ("grab a hand?" for a pallet over 120% of its estimate).
- Seed the late-manifest ledger from imported history.

**Shell**
- A queue viewer next to "N changes queued", so staff can see what hasn't synced before signing out.
